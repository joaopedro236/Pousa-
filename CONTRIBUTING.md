# Contributing to Pousa

### About

Pousa is an independently developed project focused on providing a modern, intuitive, and accessible travel platform.

This document describes the development standards and practices followed during the development and maintenance of the project.

### Development Guidelines

- Keep the code clean, organized, and readable.
- Follow the existing project architecture.
- Avoid unnecessary code duplication.
- Prioritize security, accessibility, and performance.
- Document relevant changes.
- Test features before making them available.

Commit Convention

Commits follow the Conventional Commits specification.

Examples:

- "feat: add new feature"
- "fix: correct unexpected behavior"
- "refactor: improve code organization"
- "docs: update documentation"
- "perf: optimize performance"
- "chore: update dependencies"

### Branch Naming

Branches may be used to organize features, fixes, and improvements.

Examples:

- "feat/new-feature"
- "fix/bug-fix"
- "refactor/code-improvement"

### Security

- Never commit credentials, API keys, or tokens.
- Keep sensitive environment variables in environment files.
- Validate user inputs and permissions.
- Regularly review project dependencies.

### Maintenance

Pousa is currently maintained and developed independently by its creator.

Suggestions, issues, and improvements can be documented through GitHub Issues.
